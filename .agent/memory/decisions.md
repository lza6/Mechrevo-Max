# 关键决策记录

| 日期 | 决策 | 理由 | 备选与为何不选 |
|---|---|---|---|
| 2026-10-17 | 全新自研（非魔改官方） | 主 DLL 是 .NET Native AOT 无 IL，不可反编译；且官方内存 178 MB + 多处缺陷 | 在官方基础上打补丁 → 无源码可依 |
| 2026-10-17 | Rust core + Tauri v2 + 原生 HTML/CSS/JS | 核心库可离线单测；前端零打包器，构建链最短 | Electron → 内存占用反超官方 |
| 2026-10-17 | 一切写入强制"snapshot → write_verified → 失败回滚" | 官方驱动存在把失败伪造成成功的路径 | 信任 `DeviceIoControl` 返回值 → 用户看到假成功 |
| 2026-10-17 | 禁止真机 E2E 与硬件压测，改 mock 为主 | 本机曾因 EC 泛洪/满载压测发生无转储硬复位（Event 41） | 继续真机 E2E → 反复启停驱动，风险不可控 |
| 2026-10-24 | v0.1.1 只做护栏，不加功能 | P0/P1 全部离线可修；加功能会扩大风险面 | 直接做温度/风扇曲线 → 在断裂的地基上盖楼 |
| 2026-10-24 | 限速放在 `WindowsAcpiTransport::ioctl` 内部，而非调用层 | 唯一真实硬件出口，新增路径无法绕过 | 装饰器 + `Ec::throttled()` → 可被 `Ec::new` 绕过 |
| 2026-10-24 | 回滚守卫放进 core 公共 API（`Ec::guard`） | 可被 Mock 单测覆盖，不只服务测试文件 | 只在 `hardware.rs` 里写 → 无法离线验证 |
| 2026-10-24 | 前端 IPC 命令名集中到 `IPC` 表，契约测试解析源码 | 手写两张表必然漂移；源码解析能抓真实新增 | 继续维护手写表 → 漏检（原 P2-01） |
| 2026-10-24 | 证据链用"脱敏基线文档"补，而非提交原始 JSON | 原始数据含本机特征值，越合规红线；结论可复核即可 | 提交 `ec-scan.json` → 泄露风险 |
| 2026-10-24 | 用户拍板：v0.1.1 之后做温度读数（Q-01）；证据链用脱敏基线（Q-02） | 详见 `docs/计划书/下一步改进指南.md` §17 | 工程化/产品化/多机型 → 顺延 |
| 2026-10-24 | 闸门改为"持锁覆盖整个 IOCTL" | 只 sleep 不持锁只约束起点间隔；单次 IOCTL 慢于间隔时仍重叠（复审 R1 实证） | 保留 `wait()` + 加大间隔 → 治标且牺牲吞吐 |
| 2026-10-24 | 闸门提为进程级单例 | per-instance 状态让每条命令首次访问零间隔，新路径可绕过（复审 R2 实证） | 由 app 构造一次 `Arc<Transport>` 复用 → 只解决 app，不影响未来 CLI/脚本 |
| 2026-10-24 | 复审意见按"必须修"处理，发 v0.1.2 | 能力声明超出实现属 P1 级可信度问题，与本项目"证据优先"定位直接冲突 | 只在文档里改措辞 → 典型伪闭环 |
