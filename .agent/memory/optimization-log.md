# 优化记录

| 日期 | 项 | 变化 | 影响 |
|---|---|---|---|
| 2026-10-24 | 移除死依赖 | `serde_json`、`tracing`、`tempfile` | `core/Cargo.lock` 净减约 194 行；编译依赖变少 |
| 2026-10-24 | 前端轮询治理 | 忙时暂停 + 在飞标记 | 写入期间不再产生并发 `get_status`，读数不抖；避免请求堆积 |
| 2026-10-24 | EC 访问串行化 | 单把互斥保护全部命令 | 消除"轮询与写入交错"的竞态 |
| 2026-10-24 | 访问限速下移 | 唯一 IOCTL 出口 | 新增路径无法绕过；默认 50 次/秒 |
| 2026-10-24 | 闸门持锁覆盖整个 IOCTL（v0.1.2） | `run(closure)` + 进程级 `global()` | 两次访问不再重叠；换 transport 实例也绕不过 |
| 2026-10-24 | 合并重复读 | `get_status` 只读一次 `0x751` | 每轮少 1 次 EC 访问（少 20 ms） |

## 性能基线（未做压测，仅静态估算）
- `get_status` 单轮读约 13 个寄存器；20 ms 限速下最坏 ≈260 ms；2 s 轮询占空比 ≈13%
- 常驻内存：README 声称约 52 MB（2026-10-17 观察，**未在本轮复测**）
- **禁止**用 CPU/GPU 满载压测获取"性能数据"（硬件风险）
