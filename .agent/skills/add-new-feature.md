# Skill: 新增功能（本项目）

## 适用场景
新寄存器、采样字段、页面入口、外部采集器或配置项。纯样式调整不必走完整硬件流程。

## 前置读取
`project_specs.md` → `docs/SPEC.md` → `AGENTS.md` → `test_ledger.md` → `docs/protocol/ec-baseline.md`（涉及 EC 时）→ 相关 memory/skills。

## 步骤
1. **先写清边界**：用户可见结果、来源、单位、范围、未知态、是否需要管理员/驱动/写入。能复用现有实现就不新增平行模块。
2. **先更新规格**，标出关键假设与验证方式。新 EC 地址必须实机验证，不能只信社区表。
3. **先写测试**：正常、空值、非法值、读取失败、边界；系统信息用固定 fixture，不断言某台机器的具体硬件事实。
4. **最小实现**：
   - 写硬件必须 `snapshot → write_verified → 失败回滚`，并有 RAII 回滚守卫；
   - EC 必须经统一限速闸门和互斥，外部采样不得持 EC 锁；
   - 外部进程必须有超时；异常输入不得默认为 0；
   - IPC 命令名必须同时进 `app.js` 的 `IPC` 表和后端 handler，参数走既有契约测试。
5. **前端**：正常、空、错误、禁用、确认/取消路径均真实点击验证；不把 mock 当硬件 E2E。
6. **复测接缝**：按 `test_ledger.md` 先标 `pending`，对应验证通过再 `locked`。
7. **同步文档与记忆**：README/SPEC/协议/验证台账/project_specs/change-index；写 `evidence/<task>.json`。
8. **审查**：涉及 IPC、锁、EC、节流或发布时必须独立审查，按结论修复并复验（最多 3 轮）。

## 验收标准
- 有实现、有链路、有实际命令与输出；不能只靠代码存在或文档“已完成”。
- 不把未知值、默认寄存器值、候选曲线配对说成实际生效事实。
- 代码审查 Approve 才允许完成；失败项保留明确阻塞。

## 回滚方式
代码独立提交可 `git revert`；硬件必须保存原值并能自动恢复；文档与产物同次提交，发布保留上一绿版。

## 常见坑
- 把 WMI 类存在当成硬件存在（虚拟机可有全零电池对象）。
- 把 `[N/A]` 或缺字段默认为 0。
- 外部 PowerShell/nvidia-smi 查询没有超时。
- 只把采样挪到 `open_ec()` 前，却仍持有 EC 锁。
- 温度单位忘记十分之一开尔文转 °C。
- `read_block` 跨上界静默环绕。
- 前端元素存在但未赋值（版本、日志路径等）。
