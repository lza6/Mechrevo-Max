# Skill: 计划文档闭环审计与清理

## 适用场景
项目里堆了"下一步改进指南 / 优化计划 / 待办 / 验收清单"等 md，需要判断哪些能归档删除。

## 前置读取
各计划文档本身、`project_specs.md`、`docs/VERIFICATION-LEDGER.md`。

## 步骤
1. 扫描：`find . -name "*.md" -not -path "./target/*" -not -path "./.git/*"`，筛出文件名/内容含"下一步 / 改进 / 优化 / 计划 / 指南 / 清单 / 待办 / 路线图"的
2. 逐条提取任务 → 生成台账（ID / 描述 / 来源章节 / 类型 / 优先级 / 验收标准 / 状态）
3. 判定闭环：**同时**满足 有实现 + 有链路 + 有验证 + 有证据 + 无欺骗项 + 文档一致
4. 标注"已完成"但证据缺失的 → 降级为"伪闭环"，重新验证
5. 归档：`docs/archive/plans/YYYYMMDD/` + `archive-manifest.md`（原路径/归档路径/任务统计/删除时间/回滚方式）
6. 只有"是否可删除"全为"是"才删

## 验收标准
每个文档都有明确状态（已闭环/部分闭环/伪闭环/未闭环/需决策/已过时/不适用）；删除前必有归档与 manifest。

## 证据要求
审计报告 + manifest + 删除清单表。

## 回滚方式
归档目录里保留原文件与修改时间；`git checkout <sha> -- <path>` 亦可恢复。

## 常见坑
- **含未决策项的文档不得删**（例：`docs/计划书/下一步改进指南.md` 仍含 Q-03/Q-04/Q-05 未拍板 + v0.2.0~v1.0 未完成里程碑）
- 长期路线图与 SOP 属保留例外
- 只读外部依赖里的 md（如 `~/.claude/skills/`）不属项目文档
