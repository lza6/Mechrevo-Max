# Skill: 项目终局审计 SOP

## 适用场景
要把一个项目当"即将交付的产品"重审一遍时。

## 前置读取（顺序固定）
`project_specs.md` → `docs/VERIFICATION-LEDGER.md` → `docs/SPEC.md` → `docs/ARCHITECTURE.md` §7 → `docs/protocol/ec-baseline.md` → `.agent/memory/*.md`

## 步骤
0. **技能检查**：确认 `.agent/skills/` 与本项目技术栈匹配；不匹配先补技能
1. **结构扫描**：目录树 + 行数 + 关键配置 + 入口 + 测试目录 + CI + 残留候选；排除 `target/`、`node_modules/`、`graft/`、`reverse/evidence/*.json`
2. **事实基线**：实际跑一遍只读验证（`cargo test` / `clippy` / `fmt` / 契约 / `node --check`），把输出记进证据；**不重复验证台账里标"未改动"的项**
3. **文档 vs 代码核对**：凡文档声称"已完成/已验证"，逐条找证据；找不到就降级为"伪闭环"
4. **多视角审查**：产品验收 / 架构 / 真实用户 / 调用方 / 运维部署 / 反向辩手
5. **问题分级** P0–P3，每条带 `file:line` + 判定依据
6. **最强自我反驳**：至少 3 条对本轮工作的攻击，逐条给结论
7. **盲点扫描**：交互 / 调用 / 后端 / 数据 / 衔接 / 配置 / 工程 / 测试 / 安全 / 并发 / 产品；不适用项说明原因
8. **方案对比** ≥3 个 + 权衡矩阵 → 选定 → 原子任务拆解
9. **修复 → 独立审查 → 复验**（≤3 轮）
10. **沉淀**：更新 `project_specs.md`、台账、`.agent/memory/`、技能

## 验收标准
P0/P1 清零或有明确阻塞说明；每条结论带证据等级（已验证/静态确认/合理推断/待验证）。

## 证据要求
`evidence/<task>.json`，含 `commands_executed[].raw_output_tail`。

## 回滚方式
审计本身只读；修复按任务粒度独立提交，可单点 revert。

## 常见坑
- 不要因为"文档写了已完成"就跳过验证
- 不要把"代码存在"当闭环（还要有链路 + 验证 + 证据）
- 不要在审计阶段顺手大重构
