## 五、明确"不适用"的需求（诚实界定，不假装实现）

| 用户提到的项 | 为何不适用 | 真实的对应物 |
|---|---|---|
| Load Balancer / 流量分发 | 单机桌面应用，无服务端 | — |
| CDN / 静态加速 | 无网络分发 | — |
| Redis / 缓存 | 无数据层 | 配置文件用 JSON 直读 |
| Kafka / RabbitMQ | 无跨进程消息需求 | 无（单进程） |
| Database Replication / Sharding | 无数据库 | — |
| Rate Limiting | 无对外接口 | — |
| Circuit Breaker | 无远程依赖 | → **EC 访问失败降级**（已实现：失败报错不静默） |
| Health Checks | 无服务探活 | → **EC 设备健康检查**（`probe()`，已实现） |
| Observability（Logs+Metrics+Traces） | 无服务端 | → 本地错误信息 + 可选日志 |
| SQL 注入 / N+1 | 无 SQL | — |
| 多租户 / 鉴权 | 单用户本机 | — |
| 高并发 QPS | 桌面单用户 | → **EC 访问串行化 + 设备掉线恢复**（SPEC §7） |
| 容器化 / 云部署 | 装在用户笔记本上 | — |

> 这些不是"没做"，是**场景不存在**。把它们硬塞进来只会制造复杂度，不会带来价值。
