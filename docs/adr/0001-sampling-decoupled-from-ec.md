# ADR-0001：系统采样与 EC 访问解耦

- 状态：已接受（2026-10-25）
- 范围：`app/src-tauri/src/sysinfo.rs`、`main.rs::status_snapshot`、前端状态展示

## 背景

v0.5.0 把 CPU/内存/GPU/电池/SSD 信息并入 EC 状态快照。引入了两个不同性质的依赖：

1. EC 是**必须串行化、限速**的硬件通道，每次访问需要避免重叠；
2. `nvidia-smi`、PowerShell/WMI 是独立的外部进程，可能失败、返回 `[N/A]`，也可能卡住。

如果把它们放在同一个互斥里，外部查询会把 EC 通道与用户操作一起拖住；如果把失败默认为 0，用户会把“未知”误认为“真零值”。

## 决策

1. 外部采样在**获取 EC 互斥之前**执行，任何外部查询都不能持有 EC 锁。
2. 所有外部进程使用 15 秒有界超时，超时终止并回收子进程。
3. 电池、GPU、内存等“不可知”用 `Option` 表达；缺字段、`[N/A]`、容量为 0 的电池对象都不得显示为真实 0。
4. 电池温度按 WMI 的**十分之一开尔文**转换为 °C，再做范围校验。
5. 失败保留可信缓存并标注“缓存数据/查询失败或超期”，不把旧值冒充实时值。
6. EC 不可用、传感器失败或 EC 锁中毒时，仍返回免驱系统信息。

## 取舍

- 不引入新的后台常驻采样线程或自研驱动。外部采样在现有 blocking 池执行，改动较小。
- 不用 `try/catch` 或 `unwrap_or(0)` 掩盖异常；可恢复失败转成明确的未知状态。
- 不把 EC 默认功耗寄存器或固件基线当成“系统实际生效 PL”。后者仍需要受控的内核/MSR 路径，暂不实现。

## 后果

- 电池页与 GPU/内存仪表可正确显示未知；EC 故障不再抹掉 CPU/内存读数。
- `read_block` 另行限制在 `0x0000–0x0FFF`，禁止地址回绕。
- 外部进程的实际悬挂回收仍需要专门的进程注入测试，不能只因代码有超时就宣称已验证。
- 真实 GUI、真机写入、风扇曲线写入与多机型不在本 ADR 的完成范围内。

## 验证

- `sysinfo` 固定 JSON/GPU fixture：空电池、合法磁盘、无效 GPU、合法 GPU、温度换算。
- 独立 Chromium + mock IPC：`tools/qa_browser.cjs` 覆盖 EC 不可用、未知值、曲线退避、危险确认、缓存标记。
- 真实查询脚本执行（不修改硬件）与 `ec_health.py` 低频只读检查。
