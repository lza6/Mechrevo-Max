# ADR 0002：风扇曲线写入采用「逐格写 + 读回 + RPM 停转监视」而非整表原子写

- 状态：已接受（2026-10-25，随 v0.6.0 发布）
- 关联：T-040-04；评审方案：改进指南 §19（`docs/archive/plans/20261027/下一步改进指南.md`（已归档））；独立审查 3 轮记录同上 §20.2

## 背景

风扇曲线表（EC `0x0F00`/`0x0F20`，CPU）是本项目最后一个功能缺口，也是风险最高的写入：
写错曲线可致风扇停转 → 笔记本过热。本项目已有 write_verified、RestoreGuard（RAII 回滚）、
进程级 EC 限速闸门三条护栏，但没有"写入期间风扇是否真的还在转"的行为级监视。

## 决策

采用**方案 2：逐格写入 + 每格读回 + RPM 停转监视**，并把"恢复出厂"作为内置能力：

1. 写入前 `snapshot` 两块 32 格 → `RestoreGuard` 兜底（含 panic 展开路径）；
2. 逐格 `write_settled`（3 次有界重试，复用 T-030-02 实测的固件丢写依据）；
3. 每格写完读一次 CPU 风扇 RPM，低于写入前基线 30% 立即回滚；
4. `disarm` 前再做一次最终检查（RPM 有物理滞后）；
5. 基线 RPM < 500 直接拒绝写入（防阈值 `baseline*30/100` 塌缩为 0 —— 独立审查 R1 Critical）；
6. 地址白名单 `WRITABLE_PAIRS` 仅含 CPU 表对（GPU 未做行为级验证不开放 —— R1 #2）；
7. 0xFF 填充格不写不校验（填充语义不明，写错比不写危险）。

## 被否方案

- **整表快照 + 原子写回**：写入中途失败的窗口内风扇状态未知，失败回滚本身也是逐格的，
  "原子"是假的。否。
- **只做恢复出厂、不做自定义**：用户价值过低，且恢复出厂路径已作为方案 2 的组成部分保留。

## 后果

- 正面：行为级验证（`evidence/fan-write-v2b.json`：占空比 -7% → RPM -7.1%，回滚复原）
  把"写错→过热"的暴露窗口压到单格间隔级；地址白名单阻断"合法值写错地址"。
- 负面：写入会话最坏持锁约 10 秒（32 格 × 3 重试 × 100ms + RPM 读取），期间其他 EC 命令排队——
  与所有写命令一致，可接受。
- 独立审查 R2 额外发现并修复：MockTransport 深拷贝使回滚测试断言若落在外层句柄上则恒真；
  回归测试必须经 `ec.read` 断言（`fancurve.rs::write_tests` 注释已固化此教训）。
