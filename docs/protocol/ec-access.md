# EC 访问协议（本机实测）

> 本文档记录 2026-10-16 在本机（MECHREVO 旷世16 Pro GM6PQ0X）上**实测通过**的 EC 访问方法。
> 所有结论均有证据，见 `reverse/evidence/`。

## 1. 前置条件：设备对象必须存在

官方 `UWACPIDriver.sys` 是 **KMDF PnP 驱动**，绑定硬件 ID `ACPI\INOU0000`。

该设备的定义**在 BIOS 的 DSDT 里**（`\_SB.INOU`，`_HID="INOU0000"`，无 `_STA`），
但 **Windows 启动时不会自动枚举它**。因此需要手动触发一次设备扫描：

```powershell
sc.exe start UWACPIDriver      # 1. 启动内核驱动
pnputil.exe /scan-devices      # 2. 触发 PnP 重新扫描 ← 关键
```

执行后可用以下命令确认：

```powershell
# 设备应出现，Name=ACPIDriver, Status=OK
Get-PnpDevice | Where-Object { $_.InstanceId -like '*INOU*' }
```

> **这是官方控制台的一个落地缺陷**：官方安装流程不触发这次扫描，
> 导致驱动加载却无设备可绑，EC 通道完全不可用。

| 项 | 值 |
|---|---|

| 内核对象名 | `\DosDevices\ACPIDriver` |
| 打开方式 | `CreateFileW`，`GENERIC_READ \| GENERIC_WRITE` |
| 共享模式 | `FILE_SHARE_READ \| FILE_SHARE_WRITE` |
| 驱动文件 | `C:\Windows\System32\drivers\UWACPIDriver.sys` |
| 驱动 SHA256 | `6e360ee4a0c42b2a4eaf46208c1592c87f8cd71aca2a6c52831a2ad356e61235` |

## 3. IOCTL 封包格式

### 读 EC

| 项 | 值 |
|---|---|
| IOCTL | `0x9C40A488` |
| 输入 | 4 字节，DWORD 小端 = EC 地址 |
| 输出 | 4 字节 DWORD，取低字节为结果 |

### 写 EC

| 项 | 值 |
|---|---|
| IOCTL | `0x9C40A48C` |
| 输入 | 8 字节：地址 DWORD 小端 + 值 DWORD 小端 |
| 输出 | 4 字节 |

> 官方内部用 `u16` 地址 + `u8` 数值，通过驱动时统一扩展成 DWORD。

## 4. ⚠️ "成功"不等于"生效"

社区逆向发现（并已在本项目设计上规避）：

- 官方驱动的分发例程末尾**存在把状态直接改成成功的路径**，
  因此 `DeviceIoControl` 返回 `TRUE` **不能**证明 ACPI 层真正执行了操作。
- 批量函数（`0x14030E4E0` / `0x14030E890`）**不是原子事务**，
  失败项可能被映射为 0，所以不能把所有读到的 0 当成真实测量值。

**本项目的对策**：

1. 读取失败**必须报错**，禁止用 0 代替（见 `error::Error::Ioctl`）。
2. 写入默认走 `Ec::write_verified()` —— 写完立即读回比对。
3. 任何改动前先用 `Ec::snapshot()` 存回滚点。

| EC 地址 | 含义 | 读出值 | 官方配置 |

| `0x0740` | 项目 ID | 16 | `ProjectID = 16` |
| `0x0730` | Gaming 默认 PL1 | 75 | `Default_PL1 = 75` |
| `0x0731` | Gaming 默认 PL2 | 75 | `Default_PL2 = 75` |
| `0x0732` | Gaming 默认 PL4 | 200 | `Default_PL4 = 200` |
| `0x0734` | Office 默认 PL1 | 45 | `Default_PL1 = 45` |
| `0x0735` | Office 默认 PL2 | 45 | `Default_PL2 = 45` |
| `0x0736` | Office 默认 PL4 | 200 | `Default_PL4 = 200` |

### 实时传感器

| EC 地址 | 含义 | 说明 |
|---|---|---|
| `0x0464` / `0x0465` | CPU 风扇 RPM 高 / 低 | 大端组合，实测 3970 RPM |
| `0x046C` / `0x046B` | GPU 风扇 RPM 高 / 低 | **注意低字节地址顺序相反** |
| `0x0490` | 电源来源 | 实测 7 |

### 本机不适用（需重新确认）

| EC 地址 | 社区来源含义 | 本机读出 |
|---|---|---|
| `0x0783` / `0x0784` / `0x0785` | "当前生效 PL1/PL2/PL4" | 0 |
| `0x0786` | TCC Offset | 0 |

- **2002 个非零地址**

## 7. 运行档位（性能模式）协议 ⭐ 本机已验证

档位由**两个寄存器组合**表示，改完写一次**提交寄存器**触发。

| 档位 | `0x751` | `0x7AB` | 默认 PL 来源 |
|---|---|---|---|
| 均衡 (Balance) | `0x00` | `0x00` | `0x730`–`0x732` |
| 办公 (Office) | `0xA0` | `0x00` | `0x734`–`0x736` |
| 狂暴 (Turbo) | `0x10` | `0x10` | 游戏默认值 |

**提交寄存器 `0x767`**：写入 `0x01` 触发，**固件会自动清零** ——
所以**不能对它做读回校验**，否则会误报写入失败。

### 本机实测记录（2026-10-16）

| 操作 | `0x751` | `0x7AB` | 读回 | 观测行为 |
|---|---|---|---|---|
| 起始状态 | `0x00` | `0x00` | — | CPU 风扇 3857 RPM |
| → 办公 | `0xA0` | `0x00` | ✅ 一致 | GPU 风扇 75 → 45 |
| → 狂暴 | `0x10` | `0x10` | ✅ 一致 | **GPU 风扇启动至 130 RPM** |
| → 均衡 | `0x00` | `0x00` | ✅ 一致 | 恢复 75 |
| 实验结束 | `0x00` | `0x00` | ✅ **完全恢复** | — |

实验脚本：`tools/ec_mode_exp.py`（`finally` 中强制回滚，任何异常都会恢复原值）。

### ⚠️ 机型差异提醒

本机 `0x727` 读出 `0x60`（bit 5+6），而社区记录的耀世 15 Air（EC 项目 0x1A）是 `0x80`（bit 7）。
**说明位域编码跨机型并不一致。** 档位字段 `0x751`/`0x7AB` 的编码在本机验证通过，
但其他位（如辅助覆盖位）不应照搬其他机型的结论。

### 强冷

`0x751` 的 **bit 6** 兼作强冷（Fan Boost）位 —— 与档位共用同一寄存器，
读写时必须**读改写**，不能整字节覆盖，否则会误清档位字段。
