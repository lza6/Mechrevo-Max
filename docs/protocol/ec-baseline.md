## 4.1 温度寄存器是怎么确定的（2026-10-24，自行测定）

社区两份参考实现（`roj234/mechrevo_ec_api` 的 44 个 `REG_`、`LumaDesk` 的 `ec_protocol.py`）
**都没有温度寄存器**，所以本机自己测。方法不是"数值看起来像温度"，而是**与独立参照做相关性比对**：

| 寄存器 | 参照物 | 样本 | Pearson r | 绝对偏差 | 结论 |
|---|---|---|---|---|---|
| `0x043E` | ACPI 热区 `\_sb.ectz`（`Get-Counter`） | 9 组配对 | **+0.857** | ≈ +2 °C | CPU 温度 |
| `0x044F` | `nvidia-smi --query-gpu=temperature.gpu` | 80 组并发 | **+0.989** | ≈ +1 °C | GPU 温度 |

佐证：在「静置 60 s → **单线程**升温 40 s → 冷却 60 s」实验里，`0x043E` 随参照同步上升
+5.5 °C 后回落；`0x060C`（r=+0.640，均值 78）与 `0x03A5`（在 33/49/65 三值间跳，是状态枚举）
经比对排除。

**两条必须记住的工程事实**：

1. **ACPI 温度轮询会抢同一条 EC 通道**：并发跑 `MSAcpi_ThermalZoneTemperature`（WMI）
   或 `Get-Counter` 时，直连 EC 的单次读取从 ~20 ms 恶化到 ~1.5 s（**慢 75 倍**）。
   任何"EC 采样 + ACPI 参照"的实验必须**分阶段**做。
2. WMI 的 `MSAcpi_ThermalZoneTemperature` 在本机是**冻结**的（4 分钟内恒为 66.05，
   而实际温度变化了 5 °C）；`Get-Counter '\Thermal Zone Information(*)\Temperature'` 才是活数据。

复现工具（只读、强制限速 50 次/秒、硬上限 100 次/秒）：
`tools/ec_temp_probe.py`（扫描/采样）、`tools/ec_temp_correlate.py`（三阶段相关性实验）。

## 5. 如何复现（全部只读，强制限速）

```powershell
# 0) 设备就绪（管理员 PowerShell）
sc.exe start UWACPIDriver
pnputil.exe /scan-devices

# 1) 连接探测
python -X utf8 -I tools/ec_probe.py

# 2) 关键寄存器自检（只读，50 次/秒）
python -X utf8 -I tools/ec_health.py

# 3) 与官方注册表交叉核对
python -X utf8 -I tools/ec_verify.py

# 4) 全量扫描（只读，50 次/秒，约 82 s；--interval 最小 0.01 = 100 次/秒，再快会被夹回）
python -X utf8 -I tools/ec_scan.py
```

> ⚠️ 所有工具内部强制限速（默认 50 次/秒，硬上限 100 次/秒）。**禁止**提高频率、
> **禁止**在笔记本上跑 CPU/GPU 满载压测。理由与真实事故见 `docs/SPEC.md` §5.1。

## 7. 跨机型警告

EC 地址**不通用**。已知反例：社区文档里的"当前生效 PL"地址在本机读出恒为 0；
同一字段的位域编码在不同机型上不一致（本机 `0x727 = 0x60`，耀世 15 Air 为 `0x80`）。
因此任何新机型都必须按 §5 重新实测，并在 `core/src/namespace.rs` 标注 `AddrStatus`，
不得直接沿用本表。
