# 前端冒烟验证规格（浏览器 + mock 后端）

> **这份文件是什么**：把一个"只能在真机上点"的验证，降级成**零硬件、可重复**的 DOM/交互契约检查。
> 它替代的是被用户明令禁止的真机 UI 自动化（`2026-10-17` 指示：反复启停应用会驱动硬件）。
>
> **审查边界（必须同时读）**：
> - ✅ 本验证证明：`app/ui/*` 的 DOM 契约、状态渲染、交互逻辑、IPC 参数形状、轮询生命周期正确。
> - ❌ 本验证**不证明**：真实 Tauri 窗口、真实 `invoke` 通道、真实 EC 读取、DPI/缩放、WebView2 渲染差异。
> 后者见 `test_ledger.md` 的 S4/S6（`pending`）与 `docs/SPEC.md` §5.1（真机策略）。

## 执行方式（本轮实际怎么跑的）

用 **Playwright（Chromium）** 打开 `app/ui/index.html`，在页面脚本执行**之前**注入假的 `window.__TAURI__.core.invoke`，
场景参数经 `location.hash` 传入；同时给 `setInterval` / `clearInterval` 打标，直接观测"轮询定时器是否真的被清掉"。

为什么必须这样注入：`app.js` 第一行就是 `const { invoke } = window.__TAURI__.core;`，
真实 Tauri 才会注入该全局；直接 `file://` 打开会立刻抛错，boot 不会执行。

**一个踩过的坑（必须记住）**：`page.goto(同一 URL + 不同 hash)` **不会重载文档**。
首轮因此拿到 11 条"红色失败"，全部是脚手架假象（页面还停在上一个 ready 场景）；
改为「先 `about:blank` 再带唯一 query 打开」后全部转绿。**看到红色先怀疑脚手架，再怀疑应用。**

**为什么不入库 npm 脚本**：本仓库刻意保持"前端无构建步骤、无 node_modules"（`docs/CONTRIBUTING.md` §4）。
为跑一次冒烟引入 `package.json` + playwright 依赖会破坏该设计，因此断言以规格形式记录，
执行走 MCP Playwright 或任意具备 Playwright 的环境。这是**已知边界**，不是遗漏。

## 复跑要点（换环境时）

1. 场景参数放 `location.hash`，先 `about:blank` 再带 `?run=N` 打开（避免不重载）。
2. `page.on('dialog', d => d.accept())` —— 有未应用改动时切 tab 会弹 `confirm`，不处理会卡住。
3. 断言"轮询是否停"要看 `setInterval` 注册表，不要数 `invoke('get_status')` 次数：
   动作结束后的**延迟强制刷新**（`refresh(true)` 的 `pendingRefresh`）会多出一次调用，容易被误判成"轮询没停"。
