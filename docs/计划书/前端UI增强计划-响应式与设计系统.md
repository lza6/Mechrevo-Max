## 0. 现状事实（已验证，读文件确认）

本应用是 **Tauri 2 桌面应用**，不是 Web SaaS。因此原需求中"srcset / Service Worker / 代码分包 / SEO"等纯 Web 关切**不适用**，本计划已按真实形态裁剪：

| 现状 | 事实 |
|---|---|
| 技术栈 | Tauri 2 + 原生 HTML/CSS/JS，无框架、无打包器 |
| 默认窗口 | 1000 × 680，resizable: true（tauri.conf.json） |
| 设计令牌 | `:root` 已有 oklch 色板、6/10/16/26/38px 间距、8/12/16px 圆角、220ms ease |
| 断点 | 仅 1 个：`@media (max-width: 900px)`（侧栏变顶栏）；`prefers-reduced-motion` 已处理 |
| 深浅色 | 仅深色，无 `prefers-color-scheme` 分支 |
| 无障碍 | 已有 `sr-only` / `aria-label` / `role="alert"`，基础良好 |
| 全局 | `overflow: hidden` + `user-select: none`，`font-size: 14px` 固定 |

**用户场景决定优先级**：这是笔记本硬件控制台，用户 99% 在本机 1080p/1440p/4K 屏使用，窗口可被拖到 320px 窄条（Windows 贴靠）。所以重点是**窗口级响应式 + 缩放（DPI）适配**，不是移动端触屏。

---

## 1. 执行摘要

以现有 `:root` 令牌体系为地基，做三件事：① 补全断点阶梯（320/600/900/1280）并引入 `clamp()` 流式缩放；② 补齐浅色主题与 DPI 缩放适配；③ 建立"仪表/控件/反馈"三类组件的一致性规范。全部在无构建工具的约束下完成，不引入框架——**理由**：4.76 MiB 的产物体积是本项目相对官方 178 MB 控制台的核心卖点，引入 React/Vite 会破坏这个定位。

---

## 2. 响应式策略

### 2.1 断点方案（移动优先不适用 → 采用**桌面优先 + 窄窗降级**）

现有 900px 单断点保留，追加两级：

| 断点 | 场景 | 行为 |
|---|---|---|
| `>= 1280` | 大屏/4K 缩放 150% | 内容区 `max-width: 1320px` 居中，仪表双列 |
| `900–1280`（默认） | 标准窗口 | 现状布局，不动 |
| `600–900` | 半屏贴靠 | 现有顶栏模式保留，卡片改单列 |
| `< 600` | 窄条贴靠 | 导航收为图标（`side-brand` 文字隐藏），网格全部单列，`--gap` 降为 10px |

### 2.2 流式缩放

- 根字号：`font-size: clamp(13px, 0.4vw + 12.4px, 15px)` —— 1000px 窗口 ≈ 14px（与现状一致，回归零风险）。
- 仪表尺寸用 `clamp()` 而非固定 px（现有 gauge 若为固定宽度需改）。
- 高度用 `dvh`：`html { height: 100dvh }`（Tauri WebView2 支持，`待验证`——需真机跑一次）。

### 2.3 桌面专属关切（替代移动端条款）

- **DPI 缩放**：Windows 125%/150% 缩放下 WebView2 自动适配，但需真机验证 4K@150% 下 `oklch` 渲染与 1px 边框是否发虚。
- **键盘导航**：补焦点环（`:focus-visible { outline: 2px solid var(--accent) }`），侧栏按钮支持 ↑↓ 循环。
- **触摸目标**：贴靠平板二合一设备场景下，`< 600px` 断点内按钮最小 40×40px。
- **安全区/notch**：不适用（桌面无边框窗口不跨 notch），跳过。

## 3. 性能蓝图

现状基线良好（`合理推断`：1875 行纯静态资源，无网络请求，本地 IPC 每 2s 采样）。

| 目标 | 措施 |
|---|---|
| 动画 60fps | 波纹背景 `wave` 是 `position: fixed` 全屏 repeating-gradient——若实测掉帧，加 `will-change: transform` 或降级为静态；环形仪表数字更新用 `textContent` 直写（现状已是），避免 innerHTML |
| LCP < 1s | 单 HTML 直载，天然达标，无需动作 |
| CLS = 0 | `overflow: hidden` 布局已锁定；仅需给 `#ec-alert` 等 hidden 元素预占位检查 |
| 采样节流 | app.js 2s 轮询保持；窗口 `visibilitychange` 时暂停采样（后台窗口不读 EC）——**此项同时省电** |
| 离线 | 不适用（本地应用天然离线），跳过 Service Worker |

**不引入打包器**。337 行 CSS / 1173 行 JS 未达拆分阈值；超过 800 行时再按 CLAUDE.md 规范拆文件。

## 4. 设计系统规范

### 4.1 令牌（现有基础全部保留，只增不改）

- **色板**：现 oklch 体系保留。新增浅色主题——通过 `[data-theme="light"]` 覆写同一批令牌（背景换 `oklch(97% 0.005 200)` 系，文字反转），跟随 `prefers-color-scheme` + 手动切换按钮。
- **间距**：维持 6/10/16/26/38。语义化别名可选：`--gap-page: var(--gap-lg)`。
- **圆角**：8/12/16 保留，哲学 = "容器大圆角、控件中圆角、pill 全圆"（现状已隐含，写入注释固化）。
- **阴影/海拔**：目前靠 surface-1~3 明度分层，**保持**（暗色主题下阴影几乎不可见，明度分层是正确做法，勿引入 box-shadow 体系）。
- **动效**：`--dur: 220ms` / `--ease` 保留；模态/弹层用 180ms，仅 opacity+transform。
- **字体**：仅两档（14 正文 / 11.5 辅助）已够；禁止新增第三档除非仪表大数字（可用 20px `--font-gauge`）。

### 4.2 图标

现状是 Unicode 字符（◎▤▣▮⚡≋⚙）——跨字体渲染不一致（Win10/11 Segoe 变体差异）。**建议**：换成内联 SVG sprite（约 7 个图标，<2KB），保持单文件无依赖。此项为 P2，观感收益中等。

## 6. 技术架构

- **不换栈**。Tauri 2 + 原生三件套是终态；唯一可选升级是引入 `lint`（stylelint + eslint，`待验证` node 环境可用性）。
- **目录**：维持 `app/ui/` 平铺；若 JS 超 800 行拆 `app/ui/js/{monitor,performance,cooling}.js`（ES module 直引，无需打包）。
- **主题实现**：`[data-theme]` 属性切换，持久化到 `localStorage`，Tauri 端无需改动。
- **测试策略**：无 E2E 工具（v0.1.1 台账已记录"GUI E2E 因用户禁用未执行"）。替代方案：① Playwright 连 WebView2 的 `--remote-debugging-port` 做窗口尺寸矩阵（320/600/900/1280 × 4 页面）截图比对；② 每次改 CSS 后手动贴靠左/右半屏各看一眼，截图入 `docs/screenshots/`。

- [ ] 深浅主题切换持久化，重启后保留

- [ ] EC 不可用态在窄窗口下修复命令仍完整可读
- [ ] 采样在窗口最小化时暂停（任务管理器观察 CPU）
- [ ] release 构建体积仍 < 6 MiB（体积红线）

## 9. 常见坑提示

1. **别引入框架/打包器**——会破坏 4.76 MiB 体积卖点，且与 Tauri 多余耦合。
2. **浅色主题别重画色板**——只覆写既有令牌，新增语义色等于分叉维护两套系统。
3. **900px 断点已有代码，改断点前先跑现状截图**，避免把已工作的顶栏模式改坏。
4. **`oklch` 在 WebView2 旧版（Win10 早期 build）可能不支持**——需真机验证，失败则回退 hex 等价值。
