## 2026-10-24（深夜）· v0.3.0 界面按专业监控台重做

用户反馈："强冷能不能集成？按钮太少、当前档位看不清、温度刷新频率没显示、
默认就有模式但我没设置、模式不能自定义、PL1/PL2 没显示系统值、黑匣子太多，参考 HWiNFO64"。

做的（**几乎全是把已能读到的数据正确呈现**）：
- **传感器表**：当前/最小/平均/最大 + 状态；顶栏「间隔 2.0s · 实测 x.xs · N 次」
- **强冷开关**：`0x751` bit6 读改写（不破坏档位位）+ 校验 + 回滚 + 独立撤销
- **自定义配置**：功耗墙+强冷存成一组，一键套用；坏 JSON 保留现场并降级
- **寄存器浏览器**：只读任意地址、区间展开、CSV 导出、前后端双前置校验
- **位域解释**：`751=0x40` → 「档位编码 0x00 → 均衡 / bit6 强冷 开」，并写明"档位由机器决定、启动时不写入"
- 布局：右栏 4 面板改竖排滚动（原来被裁成 2 行）

真机发现两个必须记的问题：
1. **固件偶发丢写**：强冷位 4 次往返里 1 次回写被丢（读回旧值）。排除时序/权限/提交寄存器后判定为固件行为 → 加最多 3 次「写+读回」有界重试（幂等安全），单测用"丢弃前 N 次写"覆盖
2. **布局被裁**：4 个面板塞进固定两行 grid，传感器表只显示 2 行、功耗墙被压成一条 → 改竖排 + 整栏滚动

## 2026-10-24（夜）· v0.2.0 温度读数上线 + 首次真实 GUI 端到端

### 温度是自己测出来的
社区两份参考（roj234 44 个 REG_、LumaDesk ec_protocol.py）**都没有温度寄存器**，只能自测。
判定不靠"看着像温度"，而是与**独立参照**做相关性比对：

| 寄存器 | 参照 | 样本 | r | 偏差 |
|---|---|---|---|---|
| `0x043E` CPU | ACPI 热区 `\_sb.ectz` | 9 组配对 | **+0.857** | ≈+2 °C |
| `0x044F` GPU | `nvidia-smi` | 80 组并发 | **+0.989** | ≈+1 °C |

排除项：`0x060C`（r=0.640，均值 78）、`0x03A5`（33/49/65 三值跳变 = 状态枚举）、`0x0706/0x0D51`（恒定）。

### 两条工程事实（写进基线文档了）
1. **ACPI 温度轮询会抢 EC 通道**：并发 WMI/`Get-Counter` 时单次 EC 读取从 ~20 ms 恶化到 ~1.5 s（**75 倍**）→ 参照必须分阶段读
2. WMI `MSAcpi_ThermalZoneTemperature` 在本机**冻结**（4 分钟恒 66.05，实际变化 5 °C）；`Get-Counter` 才是活数据

### 真机 bug（只有跑起来才能发现）
`0x0751 = 0x40`（bit6 强冷开 + 均衡档）→ 原 `from_field1` 按整字节匹配返回 `None` → 界面不高亮任何档位。
已改为先 `& 0xBF` 屏蔽 bit6；单测覆盖 0x40/0x50/0xE0；**真机截图确认显示「均衡」**。

### 首次真实 GUI 端到端
启动真实 exe（单次，非反复启停）→ 界面实录：CPU 72 °C「偏高」/ GPU 43 °C「正常」/
CPU 风扇 5486 RPM / GPU 风扇 5250 RPM / 供电适配器 / 均衡高亮 / `751=0x40 · 7AB=0x00` / PL 75·75·200。
内存 **62.6 MB**；release 日志确实落盘（`%LOCALAPPDATA%\Mechrevo-Max\logs`）。
截图：`docs/screenshots/app-live-window.png`

### 验证
